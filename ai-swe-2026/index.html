WORK ON THESE NOW

Four basics. No new framework required.

01 · Daily

Git and pull requests

Branch, small commits, a pull request someone else can read. This is how you show work, and how bad AI code gets caught.

02 · How systems talk

HTTP, JSON, status codes

A request, a body, and what 200, 401, 404, and 500 mean. AI tools don't do magic. They call APIs.

03 · Go deep, not wide

One language, plus SQL

Java is enough. Explain every line out loud. Then SELECT, WHERE, and JOIN. A lot of real bugs are data bugs.

04 · The actual job

Read, then change

Open one file you didn't write. Say what it does in five lines. Then change one thing without breaking the rest.

LOOK AT THE CODE · YELL IT OUT

It compiles. The demo logs in. What's wrong?

Open PR #12 LoginService.java

1+public boolean login(String email, String password) {
2+ String sql = "SELECT * FROM users WHERE email = '" + email + "'";
3+ User user = db.query(sql);
4+
5+ if (user != null && user.password == password) {
6+ return true;
7+ }

BUG 1 · THE EMAIL IS GLUED INTO THE SQL
Whatever the user types becomes part of the query. Use a placeholder, not string concat.
BUG 2 · == IS THE WRONG CHECK
In Java, == asks "same object?", not "same text?". Use equals(). AI writes this a lot.
Fix: a SQL placeholder for the email, and password.equals(...) — then you still read the diff before you merge.

0:22 – 0:25 · Let them shout. Then reveal.

  • Give them 20–30 seconds. Ask a couple of people before you click.
  • Bug 1: the email is concatenated into SQL. They’ve seen this if they took databases. You don’t need the attack string. Just: the user controls the query. Fix is a placeholder / prepared statement.
  • Bug 2: == on strings. First-year Java. AI still ships it because the happy path can pass if both sides happen to be the same object.
  • Fix: say the rule, don’t live-code it. “AI wrote a draft. You are the one who knows SQL and Java.”
  • Optional verbal extra if someone spots it: the password is compared in plain text. Don’t turn that into a third lecture.

SKILLS THAT STILL COMPOUND

The model will change. These won't.

01

Tell it what matters

The rules of the app. What not to touch. What "done" looks like. Vague prompt, vague code.

You can't brief it if you don't understand the problem.
02

Debug when it loops

AI will try the same wrong fix five times. You have to read the error and know where the system actually broke.

That's the reading muscle, again.
03

Decide what's worth building

AI will build whatever you ask. Someone still has to care about the user and cut the scope.

Taste is a practice, not a job title.
